The problem

Matches don't turn into dates.

A friend of mine matched with people and never met anyone. The problem isn't finding matches, it's conversion: you talk to a lot of people, it's all small talk, and nothing comes of it.

Research says not to promise chemistry: machine learning couldn't predict which specific pairs would be attracted to each other from 100+ traits. So Dry Run doesn't give a score. It shows where two people align, where they'd clash, and what to talk about.

Joel, Eastwick & Finkel (2017), Psychological Science.

How it works

Six steps, one real date.

1

Sign upwith a uchicago.edu email.

2

Build your clonein a ~10-minute AI interview. It saves a private profile: your values, dealbreakers, and how you handle conflict.

3

Browsea small UChicago pool and tap "interested." A mutual tap unlocks a clone date.

4

The clones go on a datea normal first conversation and a disagreement. You can watch it live.

5

Get a reportwhere you aligned, where you'd clash, and 3 conversation starters. No score.

6

"Want to meet?"If you both say yes, you see each other's contact info. A week later: "Did you meet?"

Why an interview: interview-based agents matched people's survey answers 85% as well as people matched themselves two weeks later (Park et al., 2024).

Rules

  • Clones never message real people.
  • Both people opt in before any clone date. You can delete your clone anytime.
  • The output is a reason to meet, not a score.
  • Block and report are in from day one.

Why not Volar?

Volar

  • Clone-to-clone first dates built from likes and dislikes.
  • The NYT reviewer said they rarely helped him understand the real person.
  • Two LLM clones agree with everything.

Dry Run

  • Each clone is a separate model call with a private profile and hidden dealbreakers.
  • A director agent adds friction.
  • A separate judge writes the report from a rubric.

What I learned

  • SupportsChats fizzle. People talk for days and then stop replying before anyone meets.
  • SupportsPeople can't tell if it's a good match, and they're too busy to find out by trial and error.
  • SupportsAttention is scarce. Women have a lot of matches, so most conversations get lost. A report with real things in common gives one match a reason to stand out.
  • Cuts againstThe date that did happen came from momentum, meeting the same weekend. If Dry Run is slow, it could kill that. So the clone interview happens once at sign-up, and after a mutual match the clone date and report should arrive within minutes.
  • Cuts against"We clicked through humour" and "they didn't like me" are chemistry, which clones can't predict. That's why the report gives a reason to meet, not a verdict.
Focus

Focus: AI

The part only I can build is the AI: clones that disagree honestly instead of agreeing with everything.

The app calls models itself, uses tools to run each scenario, and has evals to check how well it works. Design polish and the pool get less of my time.

Tech stack

Built on what I've shipped.

Next.js on Vercel

What I built Ironlog with. One app for the pages and the server code that calls the model.

Clerk

Sign-in, limited to uchicago.edu emails. Same as Ironlog.

Supabase

Postgres with row-level security so private clone profiles are never sent to the other person. Realtime so you can watch the date unfold, like Dockcheck's live updates.

Claude API

Haiku 5.5 for each clone's turns (a separate call per clone, so they can't read each other's private profile). Sonnet 5.5 for the judge. The director uses tool calls to add events and end scenes. About $0.06 per clone date.

Vercel Workflow

A clone date is ~70 model calls, longer than one request. Each turn runs as a step that can retry.

Eval script

Runs the test pairs from the terminal and scores mismatch detection and honest disagreement.

MCP servers
